# Обслуживание аккаунта

На экране входа нажмите **«Забыли пароль?»**, укажите email, затем введите шестизначный код из письма и задайте новый пароль. Если код уже получен, нажмите **«У меня есть код»** и укажите email аккаунта. После 5 неверных попыток код блокируется; запросите новый. Код действует 30 минут и подходит только для одного восстановления. Новый запрос отменяет предыдущий код; письма одному аккаунту отправляются не чаще одного раза в минуту. После восстановления все сессии завершаются, автоматического входа нет.

В **Профиль → Данные и конфиденциальность** доступны:

- **Сменить пароль** — требует текущий пароль; остальные сессии и ранее выданный код восстановления отменяются. На текущем устройстве вход сохраняется.
- **Завершить остальные сессии** — сохраняет вход на текущем устройстве и завершает все остальные сессии этого аккаунта.

Новый пароль должен содержать от 8 до 128 символов. В деморежиме эти действия недоступны. На устройствах с отозванной сессией потребуется повторный вход при следующем обращении к API; уже загруженные данные нельзя удалить удалённо с устройства без сети.

## Настройка сервера

Перед запуском обновлённого API примените миграции:

```sh
cd backend
uv run alembic upgrade head
```

Письма восстановления отправляются через [Gmail API](https://developers.google.com/workspace/gmail/api/guides/sending) с обычного Gmail-ящика. Собственный почтовый домен и SMTP не требуются.

### Однократное подключение Gmail

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте или выберите проект, например `MARGO`.
2. В **APIs & Services → Library** включите **Gmail API**.
3. В **Google Auth Platform** настройте название приложения и контактный email. Для обычного Gmail выберите аудиторию **External**; в режиме **Testing** добавьте Gmail отправителя в **Test users**. В **Data Access** добавьте только `https://www.googleapis.com/auth/gmail.send` — отправку писем, без чтения почты.
4. В **Clients → Create client** выберите **Desktop app** и скачайте JSON. Сохраните его в `.secrets/gmail-client.json` в корне проекта. Каталог `.secrets/` исключён из Git.
5. На своём компьютере из каталога `backend` выполните, подставив Gmail отправителя:

```powershell
uv run --group gmail-setup python -m app.gmail_setup --client-secrets ../.secrets/gmail-client.json --sender your.sender@gmail.com
```

Откроется браузер Google. Выберите **тот же ящик**, который указан в `--sender`, и разрешите отправку писем. Скрипт принимает ответ только на локальном адресе `127.0.0.1`, использует PKCE и ждёт до трёх минут. У пользователей приложения Google-доступ не запрашивается — разрешение выдаёт только владелец ящика отправителя. Скрипт не отправляет писем.

Настройки сохранятся в `.secrets/gmail.env`, значения токенов в терминал не выводятся. Скопируйте четыре строки из него в серверный `.env`. Готовый файл намеренно не перезаписывается: для повторного подключения укажите новый путь через `--output ../.secrets/gmail-new.env`.

```dotenv
MARGO_GMAIL_CLIENT_ID=your-client-id.apps.googleusercontent.com
MARGO_GMAIL_CLIENT_SECRET=your-client-secret
MARGO_GMAIL_REFRESH_TOKEN=your-refresh-token
MARGO_MAIL_FROM="MARGO <your.sender@gmail.com>"
```

Секреты хранятся только на сервере и не передаются Flutter-клиенту. Не кладите их в `.env.example` и не публикуйте JSON клиента или `.secrets/gmail.env`. Для локального запуска экспортируйте переменные в окружение процесса API: файл `.env` автоматически Python-приложением не читается.

Нужен исходящий HTTPS-доступ к `oauth2.googleapis.com` и `gmail.googleapis.com` на порт 443. Перед отправкой сервер получает короткоживущий access token по refresh token через официальную библиотеку Google Auth. SMTP и настройки Resend больше не используются. После изменения `.env` пересоздайте API-контейнер: `docker compose up -d --build api` (на VPS добавьте используемый override-файл).

### Срок действия и ограничения

В режиме **Testing** Google выдаёт refresh token для Gmail со [сроком действия 7 дней](https://developers.google.com/identity/protocols/oauth2#expiration). Для постоянной работы переведите OAuth-приложение в **In production** и заново подключите отправителя. Публикация и проверка Google — разные процедуры: `gmail.send` относится к sensitive scopes; Google может показывать предупреждение или требовать проверку в зависимости от назначения приложения. Не открывайте OAuth-доступ всем пользователям MARGO: здесь он нужен только отправителю. Смена пароля Gmail, отзыв разрешения и другие ограничения Google также могут потребовать повторного подключения.

Почтовый ящик подчиняется лимитам отправки Gmail; это вариант для небольшой нагрузки. Без любой из четырёх настроек запрос восстановления возвращает `503` для любого адреса. Остальные действия с аккаунтом работают без почтового API.

Письмо отправляется фоновой задачей процесса API после сохранения кода. При ошибке доставки сервер пишет обобщённое сообщение (для HTTP-ошибок отправки — со статусом) без email, токенов и кода; пользователь может повторить запрос через минуту. При ошибке OAuth сообщение предлагает переподключить Gmail. Тело ответа провайдера не логируется. Тайм-аут сетевых операций — 15 секунд, перенаправления отключены. Очередь не сохраняется при перезапуске процесса; гарантированная доставка с повторами пока не реализована. Успешный ответ Gmail означает приём письма сервисом, а не подтверждение доставки в ящик. Перед выпуском проверьте реальную доставку и папку «Спам».

## API

| Метод и путь | Тело | Результат |
| --- | --- | --- |
| `POST /api/auth/password/reset/request` | `email` | `202`, одинаковое сообщение для существующего и неизвестного адреса |
| `POST /api/auth/password/reset/confirm` | `email`, `token`, `new_password` | `204`; неверный, использованный или просроченный код — `400` |
| `POST /api/auth/password/change` | `current_password`, `new_password` | `204`; неверный текущий пароль — `400` |
| `POST /api/auth/logout-others` | Без тела | `204` |

Последние два метода требуют `Authorization: Bearer …`. Все четыре метода используют общий лимит авторизации — 30 попыток в минуту с одного IP. Для нескольких API-процессов требуется общее ограничение запросов на reverse proxy. Для отправки письма дополнительно действует лимит по аккаунту в базе данных. Код — 6 случайных цифр (включая ведущие нули), передаётся строкой в JSON-теле вместе с email. В базе хранится только SHA-256 с привязкой к email; бюджет из 5 неверных попыток хранится в базе и действует независимо от IP. Миграция 0004 отменяет ранее выданные длинные коды. API и Flutter-клиент нужно обновить вместе: старый клиент не поддерживает новый формат. Ответы API содержат `Cache-Control: no-store`. Код не является bearer-сессией.
