# Тематический справочник и импорт

20 направлений заданы в `backend/app/catalog.py`. Начальные подтемы (по одной на направление) и названия опорных категорий — кандидаты, а не проверенные Wikimedia ID. Импортёр проверяет существование/namespace категории и сохраняет реальные page ID и канонические заголовки. Для MVP справочник нужно вручную расширить до 80–120 подтем, отфильтровать широкие ветви и проверить качество.

Встроены **116 русскоязычных карточек** с авторскими краткими описаниями: 16 исходных (`seed-v1`) и 100 новых (`curated-v1`), по пять на каждое направление. Редакционный список находится в `backend/app/curated.py`; для каждого материала указан также английский заголовок для импорта. Тематика назначена вручную, это не результат автоматической классификации. Заголовки списка — цели импорта, их актуальность проверяется API во время загрузки.

`python -m app.seed` добавляет новые карточки в существующую базу, сохраняя прежние ID, историю, избранное и уже импортированные тексты. При обычном запуске через скрипт или Docker каталог дополняется автоматически. Демо без аккаунта в Flutter сохраняет отдельные четыре примера. Встроенные карточки не требуют запросов к Википедии, полный текст открывается в оригинале. Указанное время чтения — редакционная оценка для статьи, а не измеренная длительность чтения анонса.

## Импорт

Из папки `backend`:

```powershell
$env:WIKIMEDIA_USER_AGENT = 'MARGO/0.2 (ваш реальный контакт или URL проекта)'
uv run python -m app.seed
uv run python -m ingestion.import_catalog --source curated --limit 100 --budget 30 --language ru
uv run python -m ingestion.import_catalog --source curated --limit 100 --budget 30 --language en
```

Контакт нужно заменить реальным. Команды работают с базой из `DATABASE_URL` (по умолчанию локальная `thoth.db`); обновление локального каталога само по себе не обновляет общий сервер.

По умолчанию используется `--source curated`: до 100 целей на язык, порциями по 20 заголовков (пять запросов без повторов). Даже короткий запуск распределяет цели по направлениям. Импорт разрешает перенаправления и нормализацию заголовков, пропускает отсутствующие страницы, страницы неоднозначности, пустые введения и служебные пространства. Отчёт содержит `created`, `updated` и список пропущенных заголовков. Повторный запуск обновляет тексты и атрибуцию без смены существующих ID; английские карточки создаются только после успешного импорта, с английскими введениями. После импорта двух языков возможно до 216 карточек, если все цели разрешились и не совпали с существующими статьями.

Клиент Wikimedia использует таймаут 20 секунд, не более одного запроса в секунду, до четырёх попыток с задержкой при timeout/429/5xx/maxlag, и общий бюджет **включая повторы**. Команда завершается с ошибкой при исчерпании бюджета; уже подтверждённые записи сохраняются. Внешний импорт требует сети и корректного User-Agent; модульные тесты используют ответы-заглушки.

Прежний экспериментальный импорт через граф категорий доступен отдельно:

```powershell
uv run python -m ingestion.import_catalog --source graph --limit 300 --budget 1500 --language ru
```

Его опорные категории пока заданы по-русски: для английского каталога используйте редакционный импорт. Лимит графового режима считает новые записи, редакционного — проверяемые цели, включая обновления и пропуски.

Обход: BFS, расстояние ≤2, ближайший путь к категории, посещённые узлы не обходятся повторно, служебные названия отфильтровываются. Лимиты по категориям/ширине заданы в `classification/engine.py`. Слишком широкие ветви не разворачиваются. Вес `0.7 ** distance`; несколько совпадений направления объединяются максимумом. Версия `graph-v1` хранится в сопоставлениях и статьях. Пустая или неполная классификация попадает в `unclassified` и не рекомендуется.

Изображения Commons намеренно не импортируются до отдельной проверки лицензий; клиент использует собственную иллюстрацию и тематические заглушки. Для кратких текстов Wikipedia сохраняются источник, история авторов, ссылка CC BY-SA; полный текст открывается в оригинале. Кэш — карточка, не офлайн-копия полной статьи.

## Регулярное пополнение и контроль запаса

Отдельный процесс `workers.scheduler` проверяет запас при запуске и каждые 24 часа. Для включения нужен `WIKIMEDIA_USER_AGENT` с реальным контактом; без него планировщик пишет предупреждение и продолжает выдачу статей. Docker Compose передаёт настройки из `.env`; локально планировщик запускается отдельно: `uv run python -m workers.scheduler` из `backend`.

Порог `MARGO_CATALOG_LOW_WATERMARK=60` считается отдельно для ru/en по самому маленькому остатку среди пользователей выбранного языка (без пользователей — по всему каталогу). Если остаток ниже порога, импортируются редакционные цели, затем до `MARGO_CATALOG_BATCH=20` новых карточек из тематических категорий. Общий бюджет одного языка — `MARGO_CATALOG_BUDGET=100` запросов, включая повторы. `MARGO_CATALOG_AUTO_REFILL=false` отключает задачу. Изменение этих параметров требует перезапуска планировщика.

Категории для обоих языков заданы в `backend/ingestion/replenish.py`. Проверяются существование и namespace категории; используются только прямые участники основного пространства с введением от 100 символов. Неоднозначности и перенаправления исключаются. Темы распределяются по квоте, начальное направление меняется ежедневно. Продолжение API позволяет проходить дальше первых 500 материалов. Повторные запуски пропускают существующие page ID, сохраняют ID карточек, историю и отключённые редактором материалы. Уже подтверждённые записи остаются при сетевой ошибке; сбой одного языка не блокирует другой.

Это автоматическая классификация по прямой категории (`category-direct-v1`), а не ручная проверка качества. Пулы категорий также конечны: отчёт без роста — сигнал расширить список более узкими тематическими категориями. Отсутствующие категории и ошибки импорта видны в логах; успешный запрос ещё не означает достаточный запас. Бюджет может ограничить обход большого пула, поэтому логи и остатки нужно контролировать.

Ручной запуск и проверка без сети:

```powershell
uv run python -m ingestion.replenish --status
uv run python -m ingestion.replenish
```

`GET /api/catalog/status` (с авторизацией) возвращает `available`, личный `remaining` и флаг `low` (меньше 30 карточек) для каждого языка. Учитываются только доступные классифицированные карточки с темами. Из личного остатка исключаются все ранее назначенные, прочитанные и отмеченные «Уже знаю»; избранное само по себе запас не уменьшает. Снимок счётчиков отображается в профиле после синхронизации.

При исчерпании `GET /api/recommendations/today` возвращает 404 с объектом `detail`: `code=catalog_exhausted` (все просмотрены) или `catalog_empty` (подходящих карточек на языке пока нет), `language`, `inventory`. Клиент показывает отдельный экран со счётчиками, повторной проверкой, переходом в библиотеку и профиль. Новая карточка назначается при следующей проверке после пополнения; история не сбрасывается.

## Проверка качества

`classification.engine.evaluate` рассчитывает precision, recall, F1 по направлениям и долю неклассифицированных статей. Тесты проверяют циклы, глубину, широкие и служебные ветви и объединение весов. Размеченная людьми выборка 200–300 статей ещё не создана: реальные метрики качества не заявляются.
