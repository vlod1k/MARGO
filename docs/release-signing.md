# Подпись выпусков MARGO

## Принятое решение

Сохраняем обновление существующих Android-установок без удаления приложения.
Постоянный applicationId — `dev.thoth.thoth`. Используем прежний закрытый ключ,
явно заданный как release signing config; автоматического fallback на debug больше нет.
Историческое имя сертификата `CN=Android Debug` остаётся. Смена пароля keystore
или alias не меняет сертификат, а создание нового ключа прерывает обновления.
Этот канал предназначен для прямой установки APK. Для Google Play потребуется отдельный
план: debug-сертификат не является подходящей публичной идентичностью для магазина.

Проверенный SHA-256 сертификата существующего `0.4.3+11`:

```text
47cdf9c65e2bd828b455430785c983ba6e50a804c8c06bd6f8c21e06900a52ad
```

17 ноября 2026 ключ из локального `~/.android/debug.keystore` перенесён без изменения
сертификата в `.secrets/margo-signing/margo-release.jks`, alias `margo-release`.
У копии новый случайный пароль; локальный `apps/margo_flutter/android/key.properties`
содержит параметры доступа. Предыдущий APK сохранён как
`.secrets/margo-signing/previous-0.4.3-11.apk`. Эти файлы игнорируются системой контроля версий.
Перенос не отменяет необходимость защищать исходный debug.keystore: это тот же закрытый ключ.

## Хранение и восстановление

Ответственный за выпуск должен сохранить **вне этого компьютера** зашифрованную резервную
копию release keystore, пароли в менеджере секретов, alias и отпечаток сертификата.
Вторая независимая копия и пробное восстановление обязательны перед публичным выпуском.
Локальная `.secrets` — рабочее хранилище, не независимая резервная копия.
Не прикладывайте keystore, key.properties или пароли к issue, артефактам CI и логам.
Нельзя генерировать ключ заново при потере: обновления требуют прежней идентичности.

На новой машине скопируйте `android/key.properties.example` в `android/key.properties`,
задайте абсолютный путь с `/` и параметры из менеджера секретов. CI может передать
`MARGO_ANDROID_KEYSTORE`, `MARGO_ANDROID_STORE_PASSWORD`, `MARGO_ANDROID_KEY_ALIAS`,
`MARGO_ANDROID_KEY_PASSWORD` вместо файла. Переменные имеют приоритет.

```powershell
$env:MARGO_ANDROID_CERT_SHA256 = '47cdf9c65e2bd828b455430785c983ba6e50a804c8c06bd6f8c21e06900a52ad'
./scripts/build-android.ps1 -AllowLegacyDebugCertificate -PreviousApk .secrets/margo-signing/previous-0.4.3-11.apk
```

Проверка отклоняет debuggable APK, неправильный package, подпись, не совпадающую с
закреплённым сертификатом, и обновления с тем же или меньшим versionCode.
Исторический сертификат допускается только с явным флагом и закреплённым отпечатком.
Без параметров подписи Gradle отказывает в release-сборке; debug-сборка работает отдельно.

## Windows Authenticode

Постоянные AppId `{57EF15D1-5612-49DB-A93C-2CA03D5024E3}`, каталог установки и
имена хранилищ сохраняются. Установщик поверх старой неподписанной версии использует тот же AppId.
Подпись приложения, установщика и деинсталлятора выполняет Windows SDK SignTool с
SHA-256 и RFC3161 timestamp. Нужен доверенный code-signing сертификат издателя с
доступным закрытым ключом в `CurrentUser/My` (например, через аппаратный токен и провайдер).
Не создавайте самоподписанный сертификат для публичного выпуска.

```powershell
$env:MARGO_WINDOWS_CERT_SHA1 = '<40 hex символов отпечатка сертификата>'
$env:MARGO_TIMESTAMP_URL = '<RFC3161 URL от поставщика сертификата>'
# Если signtool не обнаруживается автоматически:
$env:MARGO_SIGNTOOL = 'C:/Program Files (x86)/Windows Kits/10/bin/<version>/x64/signtool.exe'
./scripts/build-windows.ps1
./scripts/build-windows-installer.ps1
```

Отпечаток SHA-1 здесь только выбирает сертификат; подпись файла использует SHA-256.
Проверяются доверенная подпись, точный сертификат и timestamp. Для внутренней проверки
установщика без сертификата доступен `-AllowUnsigned`; подготовка публичных обновлений
такой установщик отвергнет. ZIP из `build-windows.ps1` — отдельный неподписанный результат
первого этапа, публично распространяется проверенный Setup EXE.
При продлении Windows-сертификата обновите закреплённый отпечаток после проверки издателя.
Покупка/выпуск сертификата и доступ к его закрытому ключу пока не выполнены.

## CI и выпуск

Обычный CI собирает Android debug и release. Для release создаётся временный ключ на
каждый запуск: он не имеет доступа к постоянному ключу, включая pull request из fork.
Две release-сборки проверяют совпадение подписи и рост versionCode. Артефакт
`MARGO-Android-release-CI-ONLY` нельзя распространять пользователям.
Это статическая проверка совместимости пакетов, не установка на устройство.
Windows CI также компилирует неподписанный установщик с явным `-AllowUnsigned`;
оба Windows-артефакта помечены `UNSIGNED-CI-ONLY`.

Постоянный ключ допускается только в защищённое окружение release CI с ограниченным
доступом к секретам и проверенной веткой. Настройка удалённых секретов и запуск CI
в этой рабочей копии не выполнялись. Windows с аппаратным ключом подписывается на
выделенной машине выпуска; не передавайте токен обычным PR jobs.

```powershell
./scripts/prepare-updates.ps1 -PreviousAndroidApk .secrets/margo-signing/previous-0.4.3-11.apk -AllowLegacyDebugCertificate -Notes 'Описание изменений'
```

Эта команда требует обе закреплённые идентичности, проверяет подписи и совместимость
Android **до** записи пакетов и манифеста. Она не подтверждает реальную установку.

## Приёмка обновления на устройствах

1. В отдельном Windows-профиле/VM установите предыдущий Setup, создайте локальные
   данные и войдите в тестовый аккаунт. Запустите новый подписанный Setup через
   кнопку обновления работающего приложения. Убедитесь, что осталась одна установка,
   версия стала новой, база, настройки и сессия сохранились; проверьте запуск и удаление.
   Проверьте Authenticode у `margo.exe`, Setup и установленного `unins000.exe`.
2. На тестовом Android установите предыдущий APK, создайте офлайн-изменения,
   избранное и настройки. Из приложения установите новый APK без удаления старого.
   Проверьте versionCode, сессию, данные и последующую синхронизацию, уведомления,
   возврат из разрешений установки и повторный запуск. Для технической проверки
   можно использовать `adb install -r`; он не заменяет пользовательский сценарий.
3. Запишите модель/ОС, старую и новую версии, SHA-256 обоих пакетов, отпечатки
   сертификатов, результат и проверяющего. До этих проверок выпуск не считается принятым.

## Локальная проверка 17 ноября 2026

- Android `0.4.4+12` собран в release; проверены подпись, отсутствие debuggable,
  applicationId и совместимость сертификата/versionCode с сохранённым APK `0.4.3+11`.
  SHA-256 нового APK: `9a61dc79a03aa68a5ee87d5752ec92812578ac0ec3f6980bee03572a92fc4fd9`.
- Проверки отклонили исторический сертификат без явного разрешения, чужой отпечаток
  и пакет с тем же versionCode. Gradle отклонил release без настроенных ключей;
  конфигурация debug без release-ключей прошла (`assembleDebug --dry-run`).
- Windows: анализ, все 44 клиентских теста, release-сборка и компиляция Inno Setup
  с `-AllowUnsigned` завершились успешно. Версия установщика `0.4.4.12`;
  SHA-256: `db3749af9b67fbebfc10483028948058fe03ae69458385571af3b498dbf93943`.
  Установщик **не подписан**, публикация его через `prepare-updates.ps1` отклонена
  до создания выходного каталога. Сборка без сертификата и без `-AllowUnsigned` также отклонена.
- PowerShell-скрипты прошли синтаксический разбор, YAML workflow разобран.
  Удалённый GitHub Actions не запускался.
- Code-signing сертификаты в Windows-хранилищах не обнаружены; подключённых
  Android-устройств нет. Подписание Authenticode, реальная установка поверх предыдущей
  версии на обеих ОС и восстановление независимой резервной копии остаются непроверенными.
